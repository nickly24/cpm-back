# Документация cpm-back

Техническая документация единого бэкенда CPM: процессы, сущности, API.

## Стиль оформления разделов

Каждый файл — один предметный блок (учётки, домашки, тесты и т.д.). Внутри файла **всегда один и тот же порядок**:

1. **Обзор** — зачем раздел, что входит, 2–4 предложения.
2. **Функциональная модель** — кто что делает и видит, сценарии, ограничения по ролям (без привязки к коду).
3. **Техническая модель** — сущности, атрибуты, связи в БД (MySQL / MongoDB, если применимо).
4. **API** — эндпоинты: метод, путь, авторизация, тело запроса, ответ, сервис/модуль в коде.

Допустимы диаграммы Mermaid (ER, sequence). Если DDL таблиц нет в репозитории — схема восстанавливается из кода с пометкой «реконструкция».
