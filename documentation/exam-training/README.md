## Работа с миграцией

Миграция расширяет три существующие таблицы. Новые экзамены и все существующие экзамены получают `training_enabled=0`. Старые записи прогресса и настроек сохраняются. Миграция 013 не используется: в ней есть удаление исторических данных.

Проверка SQL без подключения к БД:

```sh
python scripts/exam_training_migration.py --plan
```

Проверка текущей настроенной БД без DDL:

```sh
python scripts/exam_training_migration.py
```

После локальных тестов и проверки восстановления приватной резервной копии:

```sh
python scripts/exam_training_migration.py --apply --backup-verified
```

Для подключения к отдельной локальной базе поддерживается `--connection-json /private/path/connection.json` с полями `host`, `port`, `user`, `password`, `database`. Файл подключения и резервные копии не добавляются в репозиторий.

Перед первым DDL проверяются состояния всех изменяемых колонок. Уже выполненные шаги проверяются и пропускаются. MySQL DDL фиксируется отдельно: при прерывании следует повторно проверить схему и продолжить миграцию, а не восстанавливать старые бизнес-данные поверх новых записей.

Резервная копия для этой операции включает `exams`, `student_card_progress`, `student_section_study_settings` и зависимую `directions`. Она проверяется восстановлением в отдельную локальную схему, репетицией 029 и сравнением всех исходных полей. Это резервная копия области изменения, а не всего приложения. Она не предназначена для удаления и пересоздания экзаменов со всеми дочерними сущностями. Изменение контрольной суммы при работающем приложении необходимо отличать от штатной параллельной записи.

## Локальные проверки

Интеграционные тесты используют явно переданный локальный Unix socket, создают уникальные схемы с синтетическими данными и удаляют только собственные схемы. Prod-подключения в тестах не используются.

```sh
PYTHONDONTWRITEBYTECODE=1 EXAM_MIGRATION_TEST_SOCKET=/absolute/local/mysql.sock \
  python -m unittest discover -s tests -v
```

Тесты импорта дополнительно создают реальный XLSX в памяти и проверяют сохранение переводов строк до вставки карточки и переноса всего ответа в черновик теста. Для frontend предусмотрены Vitest, TypeScript, ESLint изменённых файлов, production build и локальный Playwright smoke с синтетическими API-ответами и запретом внешних запросов.
