# FEX-16. Совместимость, безопасность и ввод в эксплуатацию

**Статус:** декомпозирована для разработки — [техническая постановка](../development/FEX-16-rollout.md).

## Цель

Без потери legacy-данных ввести новый домен в production и доказать его корректность под согласованной нагрузкой.

## Функциональный результат

- Старые экзамены получают тип outside LMS и `direction_id`.
- Несопоставленные старые названия направлений выявляются отчётом и маппятся вручную.
- Legacy endpoints возвращают только outside LMS до первых classic writes; CORS/error client и user-delete precheck проверены.
- Ролевые проверки закрывают каждый admin/examinator/student ресурс.
- Состояние и конкурентные команды защищены транзакционно.
- Логи не раскрывают вопросы, эталоны, голоса и импортируемые персональные данные.
- Система выдерживает до 50 одновременных комиссий при ручном обновлении.

## Контур проверки

- unit: scoring, readiness, selection, replacement, effective result;
- integration: роли, транзакции, idempotency, cascade delete, imports;
- E2E: admin, комиссия 1/6, студент, пересдача, апелляция;
- migration rehearsal на копии production-схемы;
- нагрузочный сценарий активных комиссий;
- rollback-план до включения новых маршрутов.

## Ограничения

- Направления автоматически не создаются из старых имён.
- Физическое удаление невосстановимо и требует preview.
- MongoDB не используется для classic.
- Запуск не допускается при несопоставленных обязательных legacy-направлениях.

## Зависимости

FEX-01–FEX-15.

## Критерии приёмки

- Migration rehearsal сохраняет данные; каждое исправление дублей/недопустимых значений явно учтено, без молчаливой потери.
- Все обязательные приёмочные сценарии бизнес-ТЗ автоматизированы или оформлены чек-листом.
- Нагрузочный профиль подтверждён измерениями.
- Наблюдаемость позволяет найти сдачу и correlation ID без чтения чувствительного содержимого.
- Rollout и rollback воспроизводимы по инструкции.
