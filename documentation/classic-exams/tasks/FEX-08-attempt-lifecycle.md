# FEX-08. Жизненный цикл сдачи и конкурентность

**Статус:** декомпозирована для разработки — [техническая постановка](../development/FEX-08-attempt-lifecycle.md).

## Цель

Создать надёжную логическую сдачу без realtime-транспорта, допускающую работу 1–6 равноправных членов комиссии.

## Функциональный результат

- Первый член открывает единственную ожидающую сдачу студента.
- Каждый член снимка комиссии бессрочно подтверждает готовность.
- После полного состава любой член начинает экзамен.
- Сдача сохраняется между входами и не имеет таймера.
- Начать можно только внутри периода; завершить — после окончания периода.
- Состояние обновляется собственной командой или ручной кнопкой.

## Состояния

- ожидание готовности;
- активная сдача;
- завершена.

Дополнительные текущие этапы хранятся внутри активной сдачи: выдача вопроса, голосование, конфликт, переход, спорный итог.

## Конкурентность

- `stateVersion` в каждом состоянии;
- idempotency key в каждой команде; expectedStateVersion для start/next/replace, question/round IDs для голоса, historyGeneration для ensure;
- транзакционная блокировка агрегата;
- HTTP409 для устаревшего перехода/раунда; независимые голоса и готовность разных членов не конфликтуют;
- повтор команды не создаёт дубликат; старый ensure после очистки не воскрешает удалённую историю.

## Ограничения

- Нет WebSocket, WebRTC, polling и проверки online presence.
- После старта состав не меняется.
- Админ не голосует вместо выбывшего участника.
- Не запрещено участие экзаменатора в нескольких активных сдачах.

## Зависимости

FEX-06, FEX-07.

## Критерии приёмки

- Параллельный старт создаёт одну сдачу; шесть одновременных готовностей принимаются без дополнительных обновлений.
- Старт невозможен без готовности полного состава.
- Refresh браузера восстанавливает точное состояние.
- 50 одновременных комиссий укладываются в согласованный нагрузочный профиль.
