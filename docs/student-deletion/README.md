# Удаление ученика через очередь

Администратор открывает подтверждение, видит имя ученика и объём связанных данных,
запускает удаление и получает `202 Accepted` с ID операции. Дальше работает
фоновый обработчик. Интерфейс получает прогресс каждые две секунды; закрытие окна
или перезагрузка страницы не отменяют принятую операцию.

## Хранилища и порядок

Очередь `student_deletion_jobs` хранится в существующей MongoDB. Новые коллекции
создаются обычной записью документов. Уникальный `_id` равен ID ученика; захват
операции выполняется атомарно, с восстановлением после истечения двухминутной
аренды. Очередь общая для процессов backend и переживает перезапуск сервиса.
Приложение не устанавливает SQL-таблицы, процедуры или триггеры.

1. Обработчик блокирует строку ученика и заново собирает связанные данные.
   Сохраняет ключи записей и файлов в Mongo до SQL COMMIT, чтобы сбой процесса
   после коммита не потерял сведения для дальнейшей очистки.
2. **Одной транзакцией MySQL** удаляет личные записи, очищает персональные части
   общих импортов и квитанций, удаляет аккаунт и добавляет известные ключи файлов
   в существующую `homework_s3_delete_queue`. При SQL-ошибке транзакция откатывается:
   аккаунт и все SQL-данные сохраняются, Mongo и файлы ещё не удалялись.
3. Удаляет принадлежащие ученику документы Mongo. Документы с противоречивыми
   владельцами сохраняются и попадают в отчёт для ручной проверки.
4. Файловый сервис обрабатывает свою уже существующую очередь: удаляет конкретный
   S3-ключ, проверяет отсутствие объекта через HEAD, затем подтверждает задачу.
   Используемое другим учеником вложение не удаляет. Зависшие задания повторяются.
   Backend ожидает подтверждения до десяти минут, затем сообщает о незавершённых
   ключах. Время ожидания не держит SQL-транзакцию или HTTP-запрос открытыми.
5. Проверяет оставшиеся SQL/Mongo-записи. При успехе выдаёт `completed` и 100%.
   При остатках или неизвестной принадлежности — `partial`, список таблиц,
   коллекций и ключей, а также возможность повторить очистку, где это применимо.

Mongo и S3 не входят в SQL-транзакцию. Их ошибка не восстанавливает уже удалённый
аккаунт. В интерфейсе отдельно указано, удалена ли учётная запись. Список учеников
обновляется после SQL COMMIT, даже если очистка файлов ещё продолжается.

## Подтверждение и объём

Предварительный расчёт показывает домашние работы, сдачи и известные файловые
ключи; экзамены, попытки и результаты; тесты и результаты SQL/Mongo; выученные
карточки, посещаемость и остальные связанные записи. Итог считает затрагиваемые
SQL-строки и Mongo-документы. Общая запись импорта с несколькими очищаемыми
JSON-полями учитывается один раз. Счётчики отдельных категорий могут пересекаться,
поэтому складывать их для получения итога не нужно. Файловые ключи считаются
отдельно и не являются измерением количества объектов в bucket.

Подробности включают обучение, рейтинг, посещаемость, Telegram, реквизиты входа,
экзаменационные дочерние записи, сохранённые данные прежних чатов/уведомлений,
а также персональные части общих импортов. Общие задания, вопросы, тесты,
экзамены, группы, сотрудники и данные других учеников сохраняются.

Колонка `student_id`, известные дочерние связи и фактические внешние ключи
определяют принадлежность. Если удаление по FK могло бы изменить чужие записи,
расчёт блокирует операцию; FOREIGN_KEY_CHECKS не отключается. Изменяемые
таблицы должны использовать InnoDB: нетранзакционные таблицы не допускаются
к автоматическому удалению. Неизвестные старые
форматы и неоднозначные JSON не угадываются: они показываются для ручной проверки.
Однозначные записи старого архива удаляются даже при наличии отдельного
неизвестного события, если внешние ключи допускают безопасное удаление.

Токен подтверждения привязан к администратору, ученику и составу данных, действует
пять минут. POST требует UUID `idempotency_key`. Повтор запроса возвращает
существующую операцию. Если состав поменялся до принятия операции, нужен новый
расчёт; данные, изменившиеся уже в очереди, повторно учитываются обработчиком.
Все эндпоинты требуют `users/edit`. Ответы не кешируются. Старый прямой DELETE
ученика возвращает `409 use_student_deletion_workflow`.

## API

| Запрос | Назначение |
| --- | --- |
| `GET /api/students/<id>/deletion-preview` | Имя, счётчики, предупреждения и токен подтверждения |
| `POST /api/students/<id>/deletion-jobs` | Принять фоновую операцию; `202` |
| `GET /api/students/<id>/deletion-jobs` | Найти существующую операцию ученика |
| `GET /api/student-deletion-jobs/<uuid>` | Статус, этап, прогресс и остатки |
| `POST /api/student-deletion-jobs/<uuid>/retry` | Повторить SQL после отката или очистку оставшихся хранилищ |

Статусы: `queued`, `running`, `waiting`, `failed`, `partial`, `completed`.
Этапы: `sql`, `mongo`, `files`, `verify`, `completed`.
Прогресс меняется после завершения этапов и подтверждения отдельных файлов;
он не изображает выполнение каждого DELETE внутри ещё не завершённой транзакции.

## Что требуется для выпуска

Обновить backend, файловый сервис и frontend. Используются существующие MySQL
и MongoDB и уже развёрнутая очередь файлов из базовой миграции файлового сервиса
`001_homework_pdf.sql`. **Для этой версии новые миграции MySQL не нужны.**
Если очередь файлов отсутствует, операция сообщает об этом и перечисляет ключи
для ручной очистки. Схема из прежней версии с триггерами не требуется; приложение
не применяет и не снимает её автоматически. Старые SQL-пакеты 030/031/002
исключены из текущей реализации и не должны применяться для этого сценария.

После удаления старый student JWT проверяется по существующим `students` и
`auth_users` и больше не даёт доступ. Не создаются постоянные блокировки записи,
триггеры, защитные таблицы или новые протоколы между сервисами.

Без блокировки всех писателей поздняя загрузка или старый запущенный процесс
может оставить артефакт. В известных случаях отчёт указывает остатки; он не
обещает обнаружить каждый неизвестный формат, старый объект без метаданных,
копию в журнале, резервной копии или экспорте. Не выполняется удаление bucket по
префиксу. Этот предел намеренно принят вместо общей системы запрета записи.
