## Что доказано тестами

- HTTP возвращает принятую операцию до удаления данных. Mongo-очередь сохраняет
  ID операции и возобновляет обработку после истечения аренды процесса.
- Личный SQL-граф и персональные фрагменты общих JSON удаляются/очищаются одной
  транзакцией. SQL-ошибка оставляет аккаунт и данные, не начиная Mongo/S3-удаление.
- Студент, сотрудник с совпадающим числовым ID, общие определения и другие
  ученики корректно различаются и сохраняются. Реальные FK проверяются в обе
  стороны; ограничения базы не отключаются. MyISAM не выдаётся за транзакционную
  таблицу и блокируется до первого удаления.
- Пропадание процесса между SQL COMMIT и записью статуса не теряет файловый
  список. Новый обработчик видит отсутствие ученика и продолжает внешнюю очистку.
- Ошибка Mongo не отменяет очистку файлов. Ошибка S3/HEAD не подтверждает файл
  удалённым; повтор ставит в обработку оставшиеся ключи. Коллизия регистра в
  существующем SQL-индексе очереди не считается удалением другого S3-ключа.
- Файл, уже используемый другим учеником, защищён. Mongo DELETE повторно
  проверяет поля владельца и сохраняет документ, сменивший владельца после чтения.
- Поздние SQL-строки, личные записи в общих JSON и квитанциях попадают в отчёт,
  а неоднозначные старые события не становятся поводом удалить чужие данные.
- Старый student JWT отвергается после SQL-удаления. Проверка обычного входа
  использует существующее соединение, не занимая второй слот пула.
- Backend работает в настоящем фоновом потоке; пока ожидаются файлы, статус
  доступен и прогресс находится между 0 и 100. Frontend опрашивает сервер,
  восстанавливает операцию после перезагрузки, обновляет список после SQL COMMIT,
  показывает остатки и игнорирует устаревшие ответы другой сессии.

## Стенд и ручная проверка

MySQL Community 8.0.46 и MongoDB Community 8.0.30 работают только локально.
Каждый live-тест использовал отдельную синтетическую базу. Основа — 79 таблиц
из metadata-only аудита без feature-таблиц и триггеров. До и после полного
удаления структура не меняется. Moto 5.2.3, boto3 1.40.40 и настоящий
`HomeworkStorage` проверяют S3 HTTP, DELETE и HEAD 404.

Дополнительно подняты полноценные backend и файловый сервис с отдельной
синтетической базой и локальный frontend на 3001. В браузере проверены вход,
предварительный расчёт, обязательное подтверждение, выключенная/включенная кнопка
и прокрутка окна на узком экране. После проверки подтверждение снято; оба
тестовых ученика оставлены для пользователя. Все счётчики видны на обычном
экране; на узком прокручиваются, кнопки остаются доступны.

## Пределы проверки

Production не изменялся; к нему эти прогоны не подключались. MySQL-миграции
для новой реализации не применялись и не требуются. SQL в live-фикстуре
создаёт исключительно disposable тестовые таблицы и не предназначен для prod.

Moto не проверяет реальную политику bucket, версии объектов и поздние загрузки
провайдера. Общая транзакция между SQL/Mongo/S3 отсутствует. Поздний писатель или
файл без метаданных может оставить артефакт; известные остатки показываются в
интерфейсе. Нет обещания удалить неизвестные физические копии, журналы и backups.
