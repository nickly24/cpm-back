# Классические экзамены: реализация и выпуск

Состояние на 12 сентября 2026 года. Код реализован в рабочем дереве; приложение в production из этой задачи **не развёрнуто**. Существующие несвязанные изменения пользователя сохранены. Флаги новой функциональности по умолчанию выключены.

## Production DB

- По явному решению владельца удалены старые дубли `9378`, `9999`, `10565`; сохранены более новые строки `10277`, `10000`, `10580`. Критерий — больший ID, не лучшая оценка: в старой таблице нет даты создания результата.
- Удалены все 62 результата отсутствующих студентов. Было 1422 строки, стало 1357. Остальные значения проверены неизменными.
- Перед изменениями сохранены закрытые резервные копии вне репозитория. Перед DDL восстановлена и сверена локальная копия целевых данных.
- Выполнены и повторно проверены additive-миграции **015–025 и 028**, 42 DDL-шага. Старые типы баллов и оценки пока не преобразованы. Классические экзамены и сотрудники в production не создавались.
- **026 и 027 ожидают развёртывания совместимого backend**: backfill направлений, legacy-ограничения и типы, Unicode имени экзаменатора. Нельзя выполнять этот этап поверх старого приложения.
- Миграция028 добавила только индексы очистки временных данных; [повторная проверка всех42шагов](./2026-09-12-final-additive-verification.json).
- Опубликованный production-рейтинг не пересчитывался: это остаётся явным действием администратора после включения нового расчёта.

Подтверждения: [очистка](./2026-09-12-after-cleanup.json), [миграции](./2026-09-12-migration-status.json), [исходный preflight](./initial-preflight.md).

## Что реализовано

| Область | Реализация |
|---|---|
| Экзамены и настройки | Два типа; имя из направления; постепенное заполнение; период старта; части A–Z; веса, квоты, шкала0–5 и разрешение дробного итога |
| Банк и назначения | TEXT вопрос/ответ; комиссии1–6; ручные назначения и Excel-превью; индивидуальные привилегии замен |
| Проведение | Сбор готовности; неизменяемый снимок банка; случайные вопросы и циклы; замены до первого голоса; единогласие, история расхождений, переголосования |
| Результаты | Автопубликация; одна пересдача с другой комиссией; текущий результат и история; апелляция с отметкой; физическое каскадное удаление по подтверждённому preview |
| Рейтинг | Отсутствие результата = 0; среднее по экзаменам; сохранена формула ДЗ ×0,25 + экзамены ×6 + тесты ×0,45; staging, lease и атомарная публикация; отметка устаревания |
| Совместимость | Старые API показывают только outside-LMS; дробные баллы остаются JSON-числами; защита credentials при отказе удалить ученика; права staff_admin view/edit и отдельное право загрузки |
| Интерфейс | Кабинеты администратора, экзаменатора и студента; ручное обновление экзамена; защита от устаревших ответов и повторной отправки; адаптивная раскладка |

Основной backend: `cpm_back/services/exams/`, четыре новых blueprint. Frontend: `components/exams-v2/`, `lib/exams-v2/` и интеграции существующих разделов. API namespace: `/api/exams`, `/api/examiner`, `/api/student/exams`, `/api/outside-exam-results-import`.

Изменения относительно исходного инженерного эскиза: реальная нумерация миграций начинается с015, поскольку014 уже занята ролями администраторов; legacy PK — signed INT; административные ссылки scoped по `(actor_role, actor_id)` из-за staff_admin; миграции запускаются отдельным Python CLI без Flask/MongoDB/бота. Фактические миграции и тесты являются источником истины для DDL.

Временные данные очищает bounded-worker при включённом `EXAMS_V2_ENABLED`: каждые15минут, не более12 пачек по100 строк/10секунд за проход, межпроцессная DB-блокировка. Удаляются только истёкшие import sessions и admin receipts. История сдач хранится бессрочно до явного физического удаления администратором. CLI `scripts/exams_retention.py` по умолчанию только показывает кандидатов; запись требует `--apply`.

## Проверки

- Заключительный общий backend-прогон после форматирования: **153 теста, все прошли**, включая реальные MySQL-сценарии, без пропусков. `git diff --check` обоих проектов чистый.
- Реальный локальный MySQL8.0.46: миграции, повтор после частичного DDL, ограничения, транзакции, CAS, авторизация, XLSX, пересдачи, апелляции, каскады и рейтинг.
- Шесть одновременных ready/start/vote; 120 конкурентных голосов в20раундах; гонка «замена против первого голоса»; повтор идентичной команды; консистентность деталей рейтинга при публикации и rollback после частичного UPDATE.
- Frontend: TypeScript, ESLint изменённых файлов, **53 автоматических теста**, production-сборка с явно локальным API origin.
- Реальный браузер, только localhost: вход админа, просмотр настроек/банка, сохранение вопроса с переносом строки и emoji; вход экзаменатора, ensure → ready → start → replacement → vote → auto-publish; вход студента, оба типа результатов, протокол без голосов комиссии. Тестовый classic итог —5, outside — оценка4 и баллы7,25.
- Все браузерные записи были в отдельной временной MySQL-схеме. После smoke пользователь вышел, схема удалена, процессы стенда остановлены, предоставленная вкладка возвращена в пустое состояние. Реальный student2081 не изменялся.
- [Нагрузочный профиль](./2026-09-12-local-load-final.json): 50 комиссий × 6 участников, 3380 операций, 30% конфликтных вопросов, 10% замен, 20% сдач с дополнительным вопросом — без ошибок и с проверенными итогами. Отдельно 1000 дополнительных раундов/6000 голосов и банк ровно16 МиБ/5000 вопросов. [Профиль с пулом16 соединений](./2026-09-12-local-load-pool16.json) тоже прошёл. Замеры используют Flask test client и локальный MySQL, не сетевой HTTP/WSGI.
- [Полный нагрузочный отчёт](./2026-09-12-local-load-report.md) содержит методику, распределения задержек, исправление перегрузки, повторяемую команду и ограничения замеров.
- При перегрузке добавлено ограниченное ожидание свободного соединения (до500мс), затем503 с `Retry-After`. Повторяется только получение соединения **до** транзакции, не команда/SQL. Проверен конкурентный первый POST с одним idempotency key: один экзамен, второй запрос получает replay.

Локальный MySQL не доказывает SLA production. Нужна проверка ёмкости пула и WSGI на реальном staging; mobile-поведение пока проверено кодом/адаптивными стилями, не реальным устройством. Нативная кнопка «Назад» браузера не показывает предупреждение о несохранённой форме; внутренние переходы/закрытие модалок/перезагрузка защищены.

## Как повторить

Python проекта должен быть >=3.10; проверено на3.13 с зависимостями из `requirements.txt`.

```sh
PYTHONDONTWRITEBYTECODE=1 python -m unittest discover -s tests -v
# Интеграционные тесты — ТОЛЬКО с явно заданным локальным socket:
PYTHONDONTWRITEBYTECODE=1 EXAM_MIGRATION_TEST_SOCKET=/absolute/local/mysql.sock CLASSIC_EXAM_TEST_MYSQL=1 python -m unittest discover -s tests -v
# Lifecycle suite использует cpm_exam_rehearsal на127.0.0.1:33077.
# Disposable браузерный стенд (создаёт собственную схему, удаляет при Ctrl+C):
python scripts/exams_local_smoke.py --socket /absolute/local/mysql.sock --port 8009
```

Для UI использовать **оба** локальных origin при сборке и запуске: `NEXT_PUBLIC_API_BASE_URL=http://localhost:8009` и `NEXT_PUBLIC_HOMEWORK_SERVICE_URL=http://localhost:8009`; порт frontend3007. Production URL по умолчанию в старом frontend нельзя использовать для тестовой записи. **Последняя локальная сборка `.next` содержит localhost:8009: перед production обязательно пересобрать с production origin.**

## Оставшийся порядок выпуска

1. Развернуть совместимый backend и пересобранный frontend, оставив все пять флагов выключенными. Не откатывать после первых classic-записей к прежним legacy-обработчикам.
2. Снять актуальный backup, повторить preflight, проверить активные rating jobs и mapping направлений. В согласованное окно выполнить026–027 runner с `--phase hardening --apply --backup-verified --legacy-compatible-code --direction-map <reviewed.json>`.
3. Проверить legacy outside API после DECIMAL и новые endpoints/CORS. Включить `EXAMS_V2_ENABLED` и `RATING_EXAMS_V2_ENABLED`; выполнить ручной полный пересчёт за выбранный администратором период.
4. Для пилота совместно включить `CLASSIC_EXAM_CREATION_ENABLED`, `CLASSIC_EXAM_COMMANDS_ENABLED`, `STUDENT_EXAM_RESULTS_V2_ENABLED`. Для production-пилота нужен реальный экзаменаторский аккаунт; в исходной базе examinators пуст.
5. Провести пилот на разрешённом student2081. После проверки оценок, истории и рейтинга открыть общий доступ.

Обычное выключение creation не блокирует уже начатые сдачи. Commands выключать только при аварии, сохраняя прогресс и возможность чтения. Не запускать старый разрушительный пересчёт после включения классических экзаменов.
