# Административные роли

Реализованы пользовательские административные роли с правами «Просмотр» и «Редактирование» по 18 разделам. Редактирование включает просмотр и все изменяющие действия раздела. Пользователь получает одну роль; без разрешения раздел скрыт и его API недоступен.

## Использование

После выпуска приложений обычный `admin` открывает «Доступ и роли» (`/cabinet/admin/access`):

1. Создаёт роль, задаёт название и отмечает права в таблице.
2. На вкладке «Пользователи» добавляет сотрудника: ФИО, логин, роль и при необходимости пароль.
3. Если пароль не указан, сервер генерирует его. Учётные данные показываются после сохранения однократно; пароль в БД хранится хешированным.
4. Сотрудник входит через обычную страницу входа и попадает в `/cabinet/staff_admin/...`. Кабинет использует те же административные экраны и оставляет только доступные разделы.
5. Администратор может менять роль, логин, пароль, отключать и удалять аккаунт. После сохранения аккаунта его старые сессии перестают действовать. Назначенную пользователям роль удалить нельзя.

Сам раздел «Доступ и роли» не является выдаваемой привилегией. Он доступен исключительно исходной роли `admin`. Даже `users.edit` не разрешает управлять обычными администраторами или пользователями `staff_admin` через старые методы управления персоналом.

## Матрица разделов

| Ключ | Раздел | Просмотр | Редактирование |
|---|---|---|---|
| dashboard | Главная | Главная страница и ссылки на доступные разделы | Включает просмотр; изменяющих действий на главной сейчас нет |
| users | Пользователи | Ученики, персонал, группы и фильтры | Создание, изменение, удаление, привязки групп, управление учётными данными разрешённых типов пользователей |
| schools | Школы | Школы и их ученики, непривязанные ученики | Создание/изменение школ, привязка и отвязка учеников |
| upload | Загрузка | Журналы, отчёты и результаты импорта | Загрузка, подготовка и выполнение существующих импортов |
| schedule | Расписание | Расписание, уроки и таблица | Добавление, изменение, удаление уроков, сохранение таблицы |
| telegram-bot | Telegram-бот | Состояние и настройки; токен скрыт | Настройки, токен, запуск, остановка, перезапуск |
| assignments | Домашние задания | Задания, результаты, состав и отчёты | Создание, изменение, удаление, публикация, изменение результатов |
| review-queue | Очередь работ | Активные работы и их PDF | Взять, перехватить, освободить, вернуть на доработку, оценить |
| homework-archive | Архив работ | Оценённые работы, открытие и скачивание PDF | Изменить балл, открыть пересдачу |
| monitoring | Мониторинг | Состояние обработки домашних файлов | Повторить обработку задания |
| tests | Тесты | Тесты, черновики, сдачи, попытки, история | Создание, редактирование, удаление, публикация, видимость, управление попытками/сдачами |
| test-results | Результаты | Результаты учеников и детализация | Включает просмотр; собственных изменяющих действий на этом экране сейчас нет |
| exams | Экзамены | Экзамены, сдачи и предпросмотр удаления | Существующее удаление экзаменов и связанных данных, включая групповое |
| attendance | Посещаемость | Дни занятий, записи и отчёты | Создание/изменение/удаление дней и отметок, изменение журнала, отвязка запроса на отгул |
| scan | Сканирование | Выбор дня и просмотр локальной истории сканирования | Отметка очного присутствия через ввод номера или сканирование |
| zaps | Запросы на отгул | Запросы, детали и связанные даты | Создание, обработка, повтор применения и отвязка дат |
| train | Карточки | Каталог, разделы и карточки | Создание/изменение/удаление, преобразование в тестовый черновик, существующие административные операции прогресса |
| ratings | Рейтинг | Рейтинг, детализация, отчёт, журнал пересчётов | Запуск пересчёта |

Доступ действует на весь разрешённый раздел. Ограничения по конкретной школе, группе или отдельной записи в эту модель не входят.

## Данные и миграция

`migrations/014_admin_roles.sql` добавляет:

- `admin_roles`: название, описание, даты; название уникально.
- `admin_role_permissions`: составной ключ `(role_id, section)`, `can_view`, `can_edit`; CHECK `can_edit <= can_view`; удаление прав каскадно с удалением роли.
- `admin_role_users`: ФИО, назначенная роль, активность, `session_version`, даты; FK роли с ограничением удаления.
- Последнее значение `staff_admin` в существующий enum `auth_users.role`. Общая уникальность логина сохраняется в `auth_users`.

**12.09.2026 миграция применена к продуктивной MySQL `minishep` и структура проверена.** Существующие записи не обновлялись, роли и тестовые аккаунты не создавались. Изменение enum выполнялось с `ALGORITHM=INPLACE, LOCK=NONE`.

Скрипт `scripts/apply_migration_014_admin_roles.py` выполняется отдельно от фабрики Flask. Режим `--check` читает только метаданные; обычный режим повторяемый. На этапе разработки нельзя запускать фабрику основного приложения для проверок: она инициализирует рабочие подключения и фоновые процессы.

## Проверка прав

- Основной сервер: `cpm_back/auth/admin_permissions.py` содержит явную карту конечных точек. Неизвестные операции для `staff_admin` запрещены. GET/POST не заменяют классификацию действий: некоторые старые POST только читают данные.
- Основной сервер и сервис домашних файлов заново загружают действующие права из MySQL на каждом запросе. В JWT новых аккаунтов есть версия сессии; изменение/отключение/удаление аккаунта отзывает старые токены. Права не берутся из доверенных только клиентом флажков.
- Фронт обновляет права при возврате фокуса и каждые 30 секунд. Временная сетевая ошибка не удаляет действующий токен. Серверные ограничения действуют сразу, независимо от обновления интерфейса.
- Общие справочники разрешены только как зависимости доступного раздела. `schools.edit` на общем методе изменения ученика позволяет менять только `school_id`; дополнительные поля требуют `users.edit`. `scan.edit` позволяет только очную отметку, без произвольного статуса и привязки отгула.
- При `users.view` без `users.edit` пароли скрыты. При чтении справочника без `users.view` дополнительно скрыты логины и Telegram. Токен бота доступен только при `telegram-bot.edit`.
- Просмотр черновика использует отдельное представление без блокировки/автосохранения. Просмотр попытки сотрудником не сохраняет автоматически изменение статуса истечения времени. Очередь в режиме просмотра не запускает SQL-обновление устаревших назначений прокторов.
- PDF из очереди и архива проверяются по состоянию работы; личные черновики учеников закрыты. Права архива не разрешают сбрасывать активные работы из очереди.
- Владельцы блокировок черновиков различаются по типу аккаунта и ID. Старые блокировки без типа считаются блокировками обычных администраторов.

Импорт по `upload.edit` остаётся составной операцией и может создавать связанные сущности по существующим правилам импорта. Преобразование карточек требует `train.edit`, а последующее редактирование/публикация созданного черновика — `tests.edit`.

## Выпуск

1. Миграция продуктивной БД уже выполнена.
2. Выпустить основной бэкенд и `cpm_homework_service` с проверками новой роли; после них — фронтенд.
3. Войти обычным `admin`, создать нужные роли и сотрудников через «Доступ и роли».

Код подготовлен локально; приложения в рамках этой задачи не публиковались. При откате кода новые таблицы и значение enum можно оставить. Автоматический rollback с удалением данных не предусмотрен.

## Проверки без продуктивных данных

- Основной backend: `python -m unittest discover -s tests -q` — 49 тестов. Новые проверки запрещают сетевые соединения и подставляют хранилища. В том числе перебирается вся карта конечных точек и проверяется полнота классификации административных декораторов.
- Homework service: `test_admin_roles.py` — 6 тестов; `test_auth_api.py` — 7 тестов с отключёнными соединениями. Фабрика в этих старых тестах вызывается с `initialize_services=False`, `run_worker=False`.
- Frontend: `npm test` — 31 тест; проверка типов и `npm run build` проходят.
- `cpm_front_new/scripts/admin-roles-ui-smoke.mjs` — 9 браузерных сценариев с подставными ответами API. Внешние обращения блокируются, шрифты подменяются пустым ответом. Создание роли и пользователя в этой проверке происходит исключительно в памяти теста.
- Новые frontend-модули проходят ESLint. Общий lint репозитория остаётся красным из-за существовавших ошибок React hooks и других правил; они не относятся к реализации ролей.

Для браузерной проверки запустить локальный frontend на порту 3007 с `NEXT_PUBLIC_API_BASE_URL=http://127.0.0.1:5099` и `NEXT_PUBLIC_HOMEWORK_SERVICE_URL=http://127.0.0.1:5099`. Скрипту нужен Playwright и установленный Chrome. Путь к модулю Playwright можно передать переменной `PLAYWRIGHT_MODULE` (полный путь к `index.mjs`), каталог снимков — `SMOKE_OUTPUT`. Реальный backend при этом не запускается. Эти адреса предназначены только для локальной проверки, не для сборки при выпуске.
